# Живой тест H3 (переключение co-op-режима)

Безопасная упорядоченная процедура попробовать два рычага фазы 2 из сессии 7 (`switchCoop`, `populate`)
на запущенной Far Cry 3 1.06 через `scripts/fc3_h3_trace.js`. Запускает только владелец: воздействие на
живую игру на его машине. Механизм и подтверждённое ABI — в NOTES.md «Сессия 7». Английская версия:
[h3-live-test.md](h3-live-test.md).

## Безопасность

- Только **рабочая копия** `H:\FarCryCoop\TestFC3\`. Никогда не реальная установка `H:\Uplay\Far Cry 3\`.
- Игра должна быть в **офлайн-режиме**. Инъекция Frida в онлайн / Ubisoft Connect рискует флагом
  античита; у процесса ещё страж `OpenMutexA("FarCry3Instance")`. Один экземпляр, офлайн.
- Убедитесь, что сейв одиночной игры там, где ожидаете, и примите, что живой вызов может **уронить** игру
  (мы зовём виртуал движка вне контекста диспетчера). Офлайн — риска бана нет.
- Перед первым живым (`false`) вызовом сделайте резервную копию папки сейвов рабочей копии.

## Предварительно

Frida в PATH (`frida`, `frida-ps`), игра запущена офлайн до главного меню, `FC3.dll` сборки 1.06
(скрипт перепривязывается от `base`; адреса — 1.06, база `0x10000000`).

## Шаги

1. Запустите игру офлайн и дойдите до **главного меню** (обычную миссию одиночной игры не начинайте).
2. Прицепитесь:
   ```
   frida -n FC3 -l scripts/fc3_h3_trace.js
   ```
   Должно быть видно `attached dispatch @ ...`, `attached installer/callerA/callerB` и
   `fc3_h3_trace loaded. base=...`. Если `FC3` не найден, возьмите pid через `frida-ps -a` и используйте
   `frida -p <pid> -l scripts/fc3_h3_trace.js`.
3. **Проверка только-чтение.** В REPL:
   ```
   rpc.exports.dumpService()   // this сервиса + контейнер [service+0x8c0] + install-глобалы
   rpc.exports.lastMode()      // пока null (хук диспетчера не срабатывал)
   ```
4. **Закешируйте `this` менеджера режимов.** В игре один раз войдите и выйдите из меню/лобби (например,
   откройте меню паузы или начните и выйдите миссию), чтобы хук диспетчера на `0x113405a0` сработал. Затем:
   ```
   rpc.exports.lastMode()      // thisPtr теперь должен быть не null; id = текущий режим (0x43521e6f = CO-OP)
   ```
   Строки `[dispatch] this(ebx)=... [this+0x4c]=...` в логе — живое свидетельство. Если `thisPtr` остаётся
   null, хук не срабатывает (не та сборка / не достигли) — остановитесь и сообщите, ничего не пишите.
5. **H3a сухая проба.**
   ```
   rpc.exports.switchCoop(true)   // печатает this менеджера, curMode, адрес vtable+0x5c, id
   ```
   Проверка: `vtable5c` должен выглядеть как код в `FC3.dll`, `curMode` — осмысленный текущий режим.
6. **H3a живой.**
   ```
   rpc.exports.switchCoop(false)  // пишет [this+0x4c]=0x43521e6f и зовёт vtable[+0x5c](&id)
   ```
   Следите за окном игры и логом Frida. Запишите возвращаемое значение и что произошло на экране.
7. **H3b (если H3a недостаточно).**
   ```
   rpc.exports.populate(true)     // сухая проба: this сервиса + адрес FUN_1127a0f0
   rpc.exports.populate(false)    // зовёт FUN_1127a0f0(service), чтобы построить co-op-запись
   rpc.exports.dumpService()      // перечитать [service+0x8c0] — изменился ли контейнер
   ```

## Фиксация результата

Вставьте лог Frida (особенно строки `[dispatch]` и возвращаемые значения), поведение на экране и факт
падения игры в NOTES.md (новая датированная подсекция) и обновите запись supermemory «текущее состояние».
Падение с точными значениями `this`/`vtable5c` — тоже полезный результат (оно указывает на проблему
контекста, см. дополнение к ABI в NOTES сессия 7).
